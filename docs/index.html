Method

Controller formulation

The Frenet-frame MPC generates a nominal motion command. A separate low-dimensional optimization uses a reduced dynamic model to find a nearby command within the selected effort and motion limits.

Drivetrain

Velocity-commanded skid-steer platform

u = (v, r)

Quadratic objective

The quadratic objective penalizes departure from the nominal command and from the previous output. With two variables and a positive diagonal Hessian, candidate active sets can be enumerated directly.

min ‖u − u*‖²W + ‖u − uprev‖²S

Constraints

  • Summed, differential and side-specific effort
  • Forward speed and yaw-rate bounds
  • Command slew-rate and curvature limits
  • Optional nonreversing wheel-speed constraints
Inverse model and implementation scope
τΣ = [(v − vₘ)/Tₛ + f꜀ tanh(vₘ/vε) + aᵥ vₘ + gγ] / bᵥ
τΔ = [(r − rₘ)/Tₛ + aᵣ rₘ] / bᵣ
τL = (τΣ − τΔ)/2     τR = (τΣ + τΔ)/2

The measured state is fixed during each QP, so the effort constraints are affine in the candidate command. The implementation supports forward tracking; the curvature cone does not cover reverse tracking or in-place turns. Feasibility is relative to the selected model and parameters.

The numerical solver returns an explicit infeasible status if no admissible candidate exists. The ROS adapter's zero stop request on timeout or infeasibility is not claimed to be a feasible braking trajectory.

How cross-track error is calculated

For each /tyr/odom position, calculate the shortest Euclidean distance to any line segment in /generated_path. Both streams use the map frame. All odometry samples are used, without spatial alignment or time trimming. RMS is the square root of the mean squared distance; maximum CTE is the largest distance.

The included analysis script checks SQLite integrity, reference consistency, frame agreement and SHA-256 checksums. The selected bags also contain /cmd_vel_mpc and /tyr/cmd_vel. They contain no parameter-event messages and do not independently establish the original torque-limit settings.
